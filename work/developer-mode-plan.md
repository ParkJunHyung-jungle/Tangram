# 개발자 시작 모드와 팝업 리모콘 구현 계획

작성: 2026-11-12. 상태: 구현 전 계획. 근거: 이번 사용자 요청, PRD.md §18, 현재 코드.

## 목표와 동작

- 타이틀에서 일반 시작과 개발자 시작을 선택한다. 개발자 시작은 5×6 격자, 모든 도안, 일반 몬스터 3명, 플레이어와 각 적의 체력 9999로 전투에 바로 진입한다.
- 크기는 가로 5열·세로 6행으로 해석한다. 현재 도안 7종을 모두 보유·장착하고 서로 구역이 겹치지 않게 미리 배치한다. 조각으로 도안을 미리 채우지는 않는다.
- 개발자 시작의 체력은 현재·최대 모두 9999로 설정한다. 피해는 정상 적용하며 무적이나 매 프레임 체력 복구는 넣지 않는다.
- 일반 시작은 기존 초기 조건을 사용한다. 전투 화면의 리모콘 버튼 또는 F2로 같은 팝업을 연다. 일반 게임에서도 제공한다.
- F2 재입력, 닫기, Esc로 팝업을 닫는다. 팝업 중 뒤의 배치·시전·턴 종료 입력을 차단하고, 열 때 진행 중 집기·도안 드래그·조준을 취소한다. 전역 timeScale 변경은 필요하지 않다.
- 리모콘은 조각 추가, 도안 추가, 격자 확장, 덱 편집 영역으로 구성한다. 추가 후 팝업은 유지하고 개수와 결과를 즉시 갱신한다.

## 확인할 의미와 제안 기본값

- **도안 추가:** 사용자 확인에 따라 기존 구조를 유지하고 보유 도안에 추가해 격자에 배치한다. 도안은 카드 덱에 넣지 않는다.
- **손패 제한:** 리모콘의 조각 추가는 7장 제한을 넘어 현재 손패에 들어가도록 제안한다. 자연 드로우는 기존 7장 규칙을 유지한다. 리모콘으로 늘어난 손패도 정상 배치·소모할 수 있게 표시 범위를 확장한다.
- **유지 범위:** 조각의 보유 덱 변경, 도안 보유, 격자 크기는 현재 런 동안 유지한다. 새 게임 시작 시 해당 시작 모드의 기본값으로 초기화하고 디스크 저장은 추가하지 않는다.
- 개발자 모드의 후속 전투도 일반 몬스터 3명·적 체력 9999 설정을 사용하도록 제안한다. 플레이어 최대 체력은 9999로 유지하고 전투·보상 흐름과 피해·회복은 기존 규칙을 따른다.
- 격자 확장은 행 +1, 열 +1로 제공한다. 칸 크기는 유지하고 판을 확장한다. 화면을 벗어나는 영역은 방향키로 판을 이동해 확인한다. 축소는 범위에 넣지 않는다.
- 전투 외 화면에서는 F2가 전투 상태를 새로 만들지 않게 한다. 팝업을 열 수 있게 할 경우 전투 전용 조작은 비활성화하고 이유를 표시한다.

## 구현 순서와 완료 기준

1. **시작 모드와 전투 초기화**
   - 일반·개발자 시작 경로를 기존 StartGame에 연결한다. 개발자 조건은 런 초기화 때 설정하고 일반 시작에서 초기화한다.
   - 모든 도안 획득·장착 후 5열×6행의 유효한 초기 배치를 지정한다. 일반 적은 기존 잉크 하수인의 행동을 사용한다.
   - 완료: 도안 7종이 하나씩 표시되고 일반 적 3명, 플레이어와 적 각각 현재/최대 HP 9999가 맞는다. 일반 시작은 기존 조건이다.
2. **격자 동적 크기와 화면 동기화**
   - 격자 크기의 원본은 layout 한 곳에 둔다. 확장 시 기존 도안 원점·회전·배치 조각을 보존한다.
   - 2D·3D·장착 화면의 모든 크기 참조와 숨은 숫자 기반 좌표식을 확인한다. 판이 바뀐 경우에만 필요한 형상·캐시를 재구성한다.
   - 완료: 5×6과 확장 후 가장자리 칸에서 배치·회전·클릭·시전 위치가 일치하고 기존 배치가 유지된다.
3. **리모콘과 입력 경계**
   - 버튼과 Input System의 F2를 동일한 열기/닫기 처리에 연결한다. 기존 Esc 우선순위에 팝업 닫기를 포함한다.
   - 팝업 열기 시 3D CancelPick과 UI 드래그·조준 정리를 함께 실행한다. 중복 팝업 생성과 뒤쪽 입력 전달을 막는다.
   - 완료: 일반·개발자 전투 모두 버튼/F2가 작동하고 팝업 위 클릭으로 뒤의 조각·버튼이 작동하지 않는다.
4. **조각·도안 즉시 추가**
   - 기존 CARD_POOL의 조각 정의를 읽기 전용으로 노출해 실제 지원 카드 목록을 표시한다. 임의의 미정의 모양·효과 조합은 만들지 않는다.
   - 조각 클릭마다 고유 ID의 카드 한 장을 보유 덱과 현재 손패에 연결한다. 같은 카드를 뽑기 더미에도 복제하지 않는다. 시전·버림·재셔플·다음 전투에서 정상 순환하게 한다.
   - 7장 초과 손패는 페이지 방식 등으로 모든 조각을 선택할 수 있게 하고, 3D 손패에서 같은 자리를 재사용해 겹치지 않게 한다. 페이지 전환으로 카드 상태를 바꾸지는 않는다.
   - 도안은 기존 구조 유지안 기준으로 미보유 도안을 획득·장착하고 빈 위치에 자동 배치한다. 중복 획득은 막고 이미 보유했지만 장착하지 않은 도안은 장착한다. 공간 부족 시 추가를 취소하고 격자 확장을 안내한다.
   - 완료: 조각 1회 클릭에 덱/손패가 각각 한 장 증가하고 유령 카드·중복 ID가 없다. 도안은 유효 위치에서 바로 사용할 수 있다.
5. **덱 편집과 상태 일관성**
   - 보유 덱의 카드 종류·총 수량과 손패/뽑기/묘지/배치 위치를 표시하고 추가·개별 제거를 제공한다.
   - 제거는 카드 ID를 기준으로 소유와 현재 위치에서 함께 수행한다. 배치 카드는 해당 Placement와 잔상·완성시킨 조각 참조도 정리하고 완성·시전 예상값을 다시 계산한다. 제거로 피해를 되돌리지는 않는다.
   - 추가·제거·확장 처리 전 진행 중 선택을 취소하고, 성공 후 모델→2D/3D→더미 개수를 한 번 갱신한다. 실패 시 부분 변경을 남기지 않는다.
   - 완료: 제거한 카드가 재셔플·다음 전투에 되살아나지 않고, 빈 덱에서도 드로우가 정상 종료된다.
6. **연결·검증과 기획 반영**
   - 도안 의미 확인 결과를 이 계획에 반영하고 구현 시 PRD에 목표·동작·설정·완료 기준을 추가한다.
   - Unity 컴파일 후 Editor와 Windows 빌드에서 아래 시나리오를 직접 확인한다. 테스트 코드·테스트 자산은 작성하지 않는다.

## 검증 시나리오

- 개발자 시작 → 5×6·도안 7개·일반 적 3명·모든 현재/최대 HP 9999. 시전·피격·회복 후 체력 숫자와 막대 일치.
- 일반 시작 → 기존 격자·적·체력·드로우 유지. F2와 버튼으로 팝업 열기·닫기 반복.
- 조각 추가를 반복해 손패 7장·9장을 초과 → 모든 카드 접근·배치·소모 가능. 턴 종료·재셔플·다음 전투의 수량 일치.
- 미보유/보유 미장착/이미 장착한 도안 추가, 공간 부족, 확장 후 재시도 → 중복이나 유실 없이 결과 안내.
- 행·열 확장 후 가장자리 배치·회전·도안 드래그·시전·장착 화면 진입 → 좌표·겹침 판정과 표시 일치.
- 손패·뽑기·묘지·판의 카드 각각 제거. 잔상·덧칠·완성시킨 조각 제거 후 예상 피해와 완성 판정 갱신.
- 집기·도안 드래그·시전 조준 중 F2, 팝업 중 Esc·턴 종료 클릭 → 상태가 정리되고 뒤쪽 동작 없음.
- 타이틀 복귀 후 일반/개발자 재시작 → 이전 런의 확장·덱 편집·체력 설정 초기화.
- 1920×1080·1280×720에서 큰 격자와 손패 페이지, 적 3명, 팝업이 잘리지 않음. Missing Script/Reference와 불필요한 Override 확인.

## 현재 결과

개발자 시작, 동적 격자, 리모콘, 조각·도안 추가, 덱 개별 삭제, 손패 페이지를 구현했다. 리모콘과 버튼은 기존 Canvas에 실행 중 생성해 별도 Inspector 연결이 필요 없다. C# 빌드와 Unity 재컴파일이 통과했다. Editor에서 개발자 초기값과 일곱 도안 배치, 일반 초기값, 조각 추가·삭제, 열 확장, 13장 손패의 두 번째 페이지, 팝업 입력 차단 및 Missing Script 0개를 확인했다. 마우스 드래그 전체 흐름, 다양한 해상도와 Windows 빌드 직접 플레이는 미확인이다. Git CLI를 실행하지 않았으며 저장소 변경 상태는 미확인이다.

# 주문 조각 PoC

Unity 6000.3.22f1 프로젝트다. 현재 작업 기준은 `Assets/Scenes/TestScene.unity`이며 Play를 누르면 시작 화면이 표시된다. 기존 Windows 빌드는 `Build/w10-b4-tangram-deck-building.exe`이며 아래 망치 변경을 포함해 다시 빌드하지 않았다. 게임 진행은 저장되지 않는다.

- 손패 도형을 드래그해 도안 위에 놓는다. 클릭으로 선택한 뒤 격자를 클릭하는 방식도 사용할 수 있다. R 또는 우클릭으로 회전하고 Esc로 계속하기·타이틀·종료 메뉴를 연다.
- 도안 외곽선이나 오른쪽 도안 항목을 드래그해 3행 6열 격자 안에서 옮긴다. 도안이 겹치거나 격자 밖에 놓이는 이동은 허용하지 않는다. 새 도안을 놓을 공간이 없으면 다른 도안을 옮긴 뒤 오른쪽 항목을 격자로 끌어 놓는다.
- 배치한 턴과 무관하게 조각을 이동하거나 손패로 회수할 수 있다. 손패는 최대 7장이며, 이번 턴의 미시전 배치만 회수 시 배치 횟수를 돌려준다. 각 도안 오른쪽의 포기 버튼은 해당 도안만 비운다.
- 잔상 조각은 첫 시전 뒤 남고 다음 시전 뒤 버려진다. 회수·재배치로 시전 이력을 초기화할 수 없으며, 이미 시전한 배치 비용은 환불되지 않는다. 버림 더미로 보내거나 새 전투를 시작하면 잔상 이력을 초기화한다.
- 불씨와 방벽은 각각 정사각형 한 칸과 1/4 삼각형으로 완성한다. 두 추가 도안을 모두 얻은 뒤에는 보상으로 특수 카드 4종이 모두 표시된다.
- 기본 실행 크기는 1280×720이다. 다른 화면 비율에서도 내용 전체를 중앙에 맞춰 표시한다.
- 턴 종료 위의 예상 피해는 살아 있는 적의 다음 공격 합계에서 현재 방어를 뺀 값이다. 보상 화면에서는 특수 조각의 모양이나 새 도안의 형태를 확인할 수 있다.

2026-11-09의 이전 규칙 논리 시뮬레이션에서는 불씨 반복 전략이 30회 모두 패배했고, 직사각형을 방벽에 우선 사용하는 전략은 30회 중 18회 승리했다. 현재의 1.25칸 방벽에는 직사각형을 배치할 수 없고, 당시 실험은 실제 보상 후보 제한도 반영하지 않았다. 따라서 현재 규칙의 완주 가능성·재미·난이도 검증 결과로 사용할 수 없다.

이전 버전에서 Windows 빌드 생성과 프로세스 시작을 확인한 기록이 있다. 현재 수정본의 빌드·완주 검증 결과와는 구분한다.

## 2026-11-10 수정 및 검증

잔상 카드의 시전 이력과 배치 비용 확정 상태를 분리했다. 회수·재배치 후에도 잔상 이력이 유지되고, 시전한 배치 비용은 회수·도안 포기로 환불되지 않는다. 카드·적·도안·배치 목록은 읽기 전용으로 공개한다. 도안 표시 좌표는 논리 마스크에서 생성하며, 이전 두 제작판의 미사용 도안 교체 API는 제거했다.

화면 전체를 비율에 맞춰 중앙에 배치하고, 드래그 중 회전 미리 보기·직사각형 안내 고스트·도안 전체 획득 후 네 가지 보상 배치를 수정했다. UI 갱신·비활성화 시 진행 중 드래그를 취소하고, 드래그 중 반복 전역 검색을 제거했다. 추가 Inspector 연결은 없다.

- Unity의 기존 참조와 컴파일 옵션을 사용한 전체 게임 스크립트 컴파일 통과. `.meta` 누락 및 중복 GUID 없음.
- 열려 있던 Unity의 Untitled 장면에서 자동 생성되는 게임 UI로 Play Mode 진입과 종료를 확인했다. SampleScene을 직접 연 플레이 검증과는 구분한다.
- 새 게임과 첫 손패, 클릭 배치·기본 3회 배치 차감, 첫 배치 설명, 방벽 완성 후 수동 시전·방어 7 적용·안내 종료를 확인했다.
- 적 공격 4를 방어해 체력 50 유지, 다음 턴 방어 0·배치 3회·5장 드로우, 미완성 조각 유지, 이전 턴 조각 회수 후 배치 3회 유지를 확인했다. 종료 후 Unity Console의 로그·경고·오류는 모두 0개였다.
- 잔상 회수·재배치, 네 가지 보상, 드래그 중 회전·Esc 취소, 1024×768 화면, 6전투 완주는 실제 조작 검증이 남아 있다. PRD 14절의 해당 수용 기준으로 확인한다.
- Unity Editor의 Windows Intel 64-bit 빌드가 49초 만에 성공했다. 실행 파일은 `Build/w10-b4-tangram-deck-building.exe`이며, Unity 서비스 없이 빌드했다. 컴퓨터 사용 도구가 해당 앱의 사용 미승인으로 실행 요청을 거부해 빌드 실행·직접 조작은 확인하지 못했다.
- Unity 가져오기·빌드 중 `ProjectSettings/GraphicsSettings.asset`, `ProjectSettings/ShaderGraphSettings.asset`, `Assets/Settings/PC_RPAsset.asset`, `Assets/Settings/UniversalRenderPipelineGlobalSettings.asset`의 저장 시각이 갱신됐다. 원본 대비 내용 차이는 미확인이며 기존 변경 보존을 위해 임의로 되돌리지 않았다. 빌드에서 임시 생성한 PerformanceTestRun 자산은 빌드 종료 후 자동 제거됐다.

남은 수동 확인은 SampleScene을 열고 Play → 잔상 보상 획득 → 첫 시전 후 같은 턴 회수·재배치·다음 시전으로 진행한다. 시전 직후 회수·포기에서는 배치 횟수가 늘지 않고, 다시 배치한 잔상은 다음 시전 후 버려져야 한다. 두 도안을 모두 획득한 다음 보상에는 특수 카드 네 종류가 모두 보여야 한다. Game 뷰를 1024×768로 바꿔 오른쪽 버튼이 보이는지 확인하고, 드래그 중 포인터를 멈춘 채 R·우클릭으로 미리 보기 갱신, Esc 후 계속하기에서 잔여 드롭이 없는지 확인한다.

빌드 실행 검증은 `Build/w10-b4-tangram-deck-building.exe`를 열고 시작 → 조각 배치 → 시전 → 턴 종료를 확인한 뒤 보상 선택을 포함해 6전투를 완주한다.

## 2026-11-11 망치 모드 구현 및 검증 상태

E → 손패 일반 조각 클릭 → 오른쪽 왕복 게이지에서 Space 타격 → 결과 표시 → 전투 복귀를 구현했다. 타격 전 Esc는 무료 취소이고, 일반 전투의 R·우클릭 회전 및 Esc 메뉴 경로는 유지한다. 외부 이미지 없이 uGUI 메시로 원형 나무판을 그리고 패널로 망치, 충격선, 조각 펼침을 연출한다. 추가 Inspector 참조 연결은 없다.

모델은 원본 손패 카드를 제거하고 고유 ID의 일반 결과 카드로 교체한다. 직사각형 → 정사각형 2장, 정사각형 → 반칸 삼각형 2장, 반칸 삼각형 → 1/4 삼각형 2장이다. 기존 점유 비트에서 정사각형 15는 반칸 3과 12로, 반칸 3은 1/4의 1과 2로 재구성되며 회전으로 보완 방향을 사용할 수 있다. 새 도형이나 효과를 추가하지 않았다.

타격 실패를 제거했다. 유효한 대상은 강도와 무관하게 반드시 한 번 분해된다. 이후 각 자식을 강도 × 90% 확률로 추가 분해하고 추가 분해되지 않은 자식은 그대로 남긴다. 강도 0%는 기본 분해만, 강도 50%는 자식별 추가 분해 45%, 최대 강도는 자식별 추가 분해 90%다. 따라서 정사각형·반칸·1/4이 섞일 수 있다. UI는 기본 분해 보장, 자식 추가 분해 확률과 최대 결과 수를 표시한다. 게이지 색 구분은 확정 결과의 경계가 아니다. 게이지 편도 이동 시간은 1.4초에서 0.25초로 줄여 약 5.6배 빨라졌고 왕복은 0.5초다.

원본을 교체한 손패 7장 이내에서 일부 자식을 추가 분해한다. 직사각형에서도 정사각형 1장+반칸 1장+1/4 2장 등 면적이 보존된 혼합 결과가 가능하다. 이 조합에는 최소 4장 공간이 필요해 타격 전 손패가 4장 이하여야 한다. 직사각형 전부를 1/4 8장으로 만드는 결과는 전투 제한상 불가능하다. 유효 타격은 턴당 1회 사용을 소비하며 배치 3회와는 별개다. 특수 카드도 분해하며 접착하지 않은 최소 조각은 추가 분해할 수 없다. 횟수·확률 공식·대상·지속·취소 정책은 PRD 16절의 프로토타입 가정이다.

게이지 속도·연출 시간은 SpellGameUI의 망치 프로토타입 설정 필드로 조정한다. Bootstrap이 컴포넌트를 동적으로 생성하므로 Play 중 Inspector 변경은 해당 실행에만 적용된다. 기본값을 지속적으로 변경하려면 필드 초기값을 변경한다. 턴당 사용 횟수는 SpellGame의 HAMMER_USES_PER_TURN, 최대 조각별 성공 확률은 MAX_DECOMPOSITION_CHANCE 상수다. UI 미리 보기는 난수를 소비하지 않는다.

상점 재사용을 위해 공통 계산 SpellGame.DecomposeShape(shape, strength, maxPieces, random)를 공개한다. 반환값은 혼합 Shape 배열이며 카드·전투·덱 상태를 변경하지 않는다. 최대 결과 수와 난수원은 호출자가 전달한다. 전투의 TryHammer만 손패와 사용 횟수를 변경하며, 향후 상점은 비용과 소유 덱 적용을 별도로 처리하면 된다. 상점 화면이나 영구 덱 변환은 이번에 구현하지 않았다.

카드 변환은 Space 입력 시 원자적으로 확정하고 애니메이션은 확정된 결과만 표시한다. 연출 중 UI 재생성·비활성화에도 카드가 재생성되지 않는다. 원정 소유 덱은 수정하지 않아 같은 전투에서는 결과가 버림·드로우로 유지되고 다음 전투에서는 원본 덱으로 복귀한다.

실제 확인 결과:

- Unity 6000.3.22f1의 기존 Bee 참조·컴파일 옵션으로 새 그래픽을 포함한 게임 C# 컴파일 통과.
- 기본 분해 보장·추가 분해 확률·편도 0.25초 게이지로 변경 후 C# 컴파일을 통과했다. 변경 후 실제 타격과 드래그·게이지·UI 표시는 아직 Play Mode에서 확인하지 않았다.
- Unity Editor의 TestScene에서 Play Mode 진입, 시작 버튼 클릭, 전투 화면과 E 망치 남은 횟수 표시, Play Mode 종료 확인.
- 해당 실행 종료 후 Unity Console의 로그·경고·오류가 모두 0개임을 확인했다. 스크립트 `.meta` 누락과 Assets 내 중복 GUID도 없었다.
- 자동 조작의 E 키 입력에서 망치 화면 진입이 관찰되지 않았다. 이전 입력 검증에서도 키 전달 문제가 있어 원인은 확정하지 않았다. E·Space의 실제 수신, 게이지·연출·분해 카드 배치 및 기존 기능 회귀는 미검증이다.
- 면적 보존과 카드 소유권·손패 경계는 코드 검토 결과이며 실제 플레이 통과로 간주하지 않는다. 테스트 코드·프레임워크·테스트 자산은 추가하거나 수정하지 않았다. 망치 변경 후 Windows 빌드는 수행하지 않았다.

수동 확인 절차:

1. TestScene을 열고 Play → 시작. Game 뷰에 포커스를 두고 E를 누른다. 대상 선택 전 Space는 아무 카드도 바꾸지 않아야 한다.
2. 정사각형 등 일반 손패를 클릭하거나 원형 작업대 안으로 드래그한다. 게이지가 왕복 0.5초로 움직이고 기본 분해 보장 및 자식 추가 분해 확률이 표시되는지 본다. 작업대 밖 드롭은 선택을 바꾸지 않아야 한다. 1/4 조각은 거부 사유를 확인한다.
3. 서로 다른 새 턴에서 약한 강도와 강한 강도로 여러 번 타격한다. 낮은 강도에서도 기본 분해는 반드시 되고, 강할수록 추가 분해가 많아지는지 비교한다. 손패 5장이면 결과를 최대 3장까지, 4장이면 최대 4장까지 넣을 수 있다. 직사각형은 손패 4장 이하에서 1/4이 섞이는 결과를 확인한다. 생성 카드를 기존 도안에 배치하고 R·우클릭 회전, 수동 시전을 확인한다.
4. 타격 전 Esc 후 원본·사용 횟수 유지, 타격 후 같은 턴 E 재사용 거부, 다음 턴 횟수 복구, 손패 7장일 때 선택 거부를 확인한다. Space 연타·누른 채 유지에도 한 번만 처리되어야 한다.
5. 반칸·직사각형, 특수 카드, 버림·다시 뽑기·다음 전투 원복, UI 비활성화·재활성화와 1024×768·넓은 화면을 확인한다. 이후 PRD 14절의 회수·잔상·보상·재시작 회귀 항목을 진행한다.

손패 제한과 1/4 생성의 충돌은 사용자가 승인한 혼합 분해로 반영했다. 최대 90% 추가 분해 확률은 임시 밸런스 값이다. 기존 빌드 설정의 SampleScene은 이번 작업에서 변경하지 않았다. Git CLI를 사용하지 않아 저장소 전체 변경 상태는 미확인이다.

## 2026-11-11 Q키 접착 구현

TestScene의 기존 Bootstrap을 유지하고 Q 또는 접착 버튼으로 작업대를 연다. 일반·특수 기본 도형 카드 두 장을 클릭하거나 손패에서 작업대로 드래그해 선택한다. 중앙 8×4 작업 공간에서 드래그·칸 스냅·R 또는 우클릭 회전으로 실제 변을 맞춘 뒤 확인한다. 빈 칸 클릭으로도 이동하며 회전 버튼을 제공한다. 조각 전체가 작업 공간 안에 남도록 이동·손패 드롭·회전 후 위치를 제한한다. 두 장 미선택·재접착·겹침·꼭짓점 접촉·틈은 거부하며 이유를 표시한다. Esc 또는 취소는 무료다. 접착과 망치를 동시에 열거나 접착 중 Space로 확정할 수 없다.

접착 카드는 기존 네 가지 기본 도형과 별도의 새 Shape enum이 아니라 선택적 GluedShape 데이터로 표현한다. 원본 두 카드 참조와 ID, 각 회전, 상대 위치, 정규화한 점유 마스크를 보관한다. 기본 카드와 복합 카드의 실제 렌더링·선택·배치·미리 보기·완성 판정은 공통 CellMask를 사용한다. 삼각 구역이 겹치지 않으면서 같은 칸의 인접 구역 또는 이웃 칸의 마주 보는 변을 공유해야 하므로 빈 공간을 채우거나 꼭짓점 접촉을 접착으로 취급하지 않는다.

확인 시 손패 카드와 접촉을 다시 검증해 원본 두 장을 한 장으로 교체한다. 접착 자체는 배치 횟수를 소비하지 않고, 전체를 도안에 배치할 때 1회 차감한다. 이동·회수·미시전 환불도 카드 하나 기준이다. 턴당 접착 1회이며 망치 사용권과 별개다. 같은 전투의 버림·다시 뽑기에서 합성 정보는 유지된다. 원정 소유 덱을 수정하지 않으며 전투 승리·패배·타이틀 복귀 시 임시 전투 카드와 배치를 정리하고 보상 카드를 포함한 소유 덱으로 복구한다. 다음 전투와 재시작에서 복합 카드가 남지 않는다.

원래 도안에 맞지 않는 긴 모양을 붙일 수도 있다. 해당 카드는 실제 전체 영역이 맞는 도안에서만 배치 가능하며 임의로 축소하지 않는다. 접착 카드는 재접착에서 제외하지만 망치로 분해할 수 있다. 기본 타격으로 두 구성 조각을 분리하고 강도에 따라 각 조각을 추가 분해한다. 1/4 둘을 붙인 카드도 해제 가능하며 손패 7장과 면적을 보존한다. 망치 화면의 대상·손패 아이콘도 실제 복합 마스크로 표시한다. Inspector에서 연결할 참조는 없으며 씬·패키지·입력 설정을 변경하지 않았다.

변경 파일은 SpellGame.cs, SpellGameUI.cs, SpellBoardGraphic.cs, SpellShapeGraphic.cs, 신규 SpellGlueGraphic.cs와 .meta, PRD.md 및 README.md다. 테스트 코드·프레임워크·자산은 추가·수정하지 않았다. 새 Windows 빌드는 생성하지 않았다.

수동 확인 예시: 시작 손패의 정사각형과 1/4 삼각형을 선택한다. 정사각형 아래 칸에 위쪽을 점유하는 1/4 삼각형을 붙여 확인하고, 결과 카드 하나를 방벽의 위 칸에 배치하면 전체 도안이 완성되어 배치 1회로 방어 7을 시전할 수 있다. 회수·턴 넘김·재접착 거부·다음 턴 사용권·재드로우·전투 종료 원복도 이어서 확인한다. 보완 반칸 둘은 같은 칸에서 회전을 2회 차이로 맞추면 정사각형 모양으로 접착 가능하고, 마주 보는 1/4 둘은 중심 꼭짓점만 만나므로 같은 칸에서 접착 불가여야 한다.

최소 검증 결과:

- 새 작업 공간 그래픽을 포함한 게임 C# 컴파일 통과. 스크립트 .meta 누락과 Assets 내 중복 GUID 없음. Unity 자산 새로고침 후 TestScene Play Mode에서 최신 접착 UI와 전투를 실행했다.
- 클릭 경로로 접착 작업대 진입, 원본 정사각형·1/4 선택, 선택 부족·틈·겹침·회전으로 꼭짓점만 닿는 상태의 거부, 네 번 회전 후 접착 가능 상태 복구를 확인했다.
- 확인 후 손패 5장→4장, 접착 사용권 1→0, 기본 배치 3회 유지. 복합 카드 전체를 방벽에 배치해 도안 완성과 배치 3→2를 확인했다.
- 복합 카드를 한 장으로 회수해 배치 2→3 환불, 같은 카드 재배치 후 방벽 수동 시전으로 방어 7·버림 1·제작 중 0을 확인했다. 다음 턴 체력 50·방어 0·배치 3·접착 사용권 1·5장 드로우도 확인했다.
- 자동 조작의 Q 키와 드래그로는 진입·이동이 관찰되지 않았다. 원인은 확정하지 않았으며 Q·R·Esc·Space의 실제 키 수신 및 드래그는 미검증이다. 위 이동·회전 검증은 빈 칸 클릭과 회전 버튼으로 진행했다.
- 사용자의 최소 검증 요청에 따라 추가 조합·다른 해상도·전투 완주·접착 카드 재드로우·전투 종료 원복·보상 보존·재시작·잔상 및 망치 회귀 조작은 추가 실행하지 않았다. 이 항목들은 구현 경로 검토와 실제 플레이 통과를 구분한다.

후속 수정: 손패 카드에 기존 SpellCardDrag를 연결하고 접착 모달의 드롭 경로를 추가했다. 작업 공간 드래그는 임계 거리를 넘은 현재 포인터가 아닌 최초 pressPosition으로 잡은 조각을 찾도록 수정했다. 이전에는 조각이 격자 밖으로 그려지지만 해당 영역에서는 UI 레이캐스트를 받지 못해 다시 잡을 수 없었다. 모든 이동과 회전에 도형 크기를 반영한 경계 제한을 적용해 밖으로 나가지 못하도록 변경했다. 접착 카드 망치 분해도 연결했다. 이 후속 변경은 C# 컴파일 통과만 확인했고, 최소 검증 요청에 따라 Play Mode를 추가 실행하지 않았다.

접착 작업대에서 드래그 중 R은 현재 잡은 조각을 회전한다. 잡은 지점도 함께 회전시켜 포인터가 정지해 있어도 점유·접촉 표시를 즉시 갱신하며 경계 제한을 유지한다. 손패에서 작업대로 드래그하는 도중에도 미리 보기를 회전하고 드롭 시 방향을 보존한다. 이 변경은 C# 컴파일 통과만 확인했으며 실제 드래그 중 키 입력은 미검증이다.

특수 조각 분해·접착: 원본마다 가장 큰 결과 한 장에만 특수 효과를 남기고, 최대 크기가 같으면 균등 무작위로 선택한다. 접착 카드 분해에서도 각 구성 원본의 결과 안에서 별도로 효과를 배분한다. 접착 카드의 시전·미리 보기는 두 원본 효과를 모두 합산하며 불꽃 둘이면 피해 +4, 수호 둘이면 방어 +6이다. 잔상은 접착 전체에 적용하고, 이미 사용한 이력은 접착·분해로 초기화하지 않는다. 회수·재배치 시 비용 확정 상태와 잔상 이력은 기존처럼 분리한다. 특수 1/4은 단독으로 더 나눌 수 없지만 다른 조각과 접착하거나 접착 상태에서 다시 분리할 수 있다. 카드 이름과 색상도 합성 효과를 표시한다. 이 변경은 C# 컴파일 통과만 확인했으며 특수 보상 획득 후 실제 조작 검증은 추가하지 않았다.

## 2026-11-11 형상 봉인자

TestScene 시작 화면의 `형상 봉인자 전투` 버튼으로 진입한다. 기존 `시작` 버튼과 SampleScene의 5전투+보스 진행은 보존한다. 별도 진입 첫 전투에는 기존 잉크 하수인과 형상 봉인자가 함께 등장한다. 봉인자의 HP 12·공격 4는 하수인 설정을 재사용한 임시값이다. 첫 행동 전에 봉인하며, 이 진입에서는 첫 주문 튜토리얼을 생략한다. 다음 전투 배치와 정식 수치는 아직 정하지 않았다.

모델은 봉인자별 현재·직전 고유 주문 ID를 보관한다. 현재 보유 도안은 UI 오른쪽 목록에 모두 표시되므로 이 목록과 동일한 Spells에서 선택한다. 도안 이동은 ID를 바꾸지 않는다. 봉인 도안으로의 신규 배치·내부 재배치와 시전을 모델에서 차단하며, 완성 여부와 기존 배치 목록은 바꾸지 않는다. 회수·도안 포기·봉인 밖으로 이동은 기존 경로를 유지한다. UI는 실제 도안 위치에 가느다란 수직 막대기와 잠금 표시를 그리며 이름·테두리·미리 보기·시전 버튼 상태도 갱신한다. 막대기는 포인터 입력을 가로채지 않는다.

시전 피해를 공통 DamageEnemy로 전달해 실제 HP가 줄어든 봉인자의 봉인만 즉시 해제한다. 다른 적 피격과 피해 0은 영향을 주지 않는다. 해제 직후 재봉인하지 않으며, 턴 종료 시 기존 적 공격 처리 후 살아 있는 봉인자만 직전과 다른 도안으로 변경한다. 도안 하나면 재선택, 없으면 미생성이다. 적 사망·전투 종료·타이틀·재시작에서 봉인을 정리한다. 기존 3×6 격자·주문 수치·카드·망치·접착 규칙은 변경하지 않는다.

변경 파일: SpellGame.cs, SpellGameUI.cs, PRD.md, README.md. 새 씬·테스트 코드·테스트 자산·패키지는 추가하지 않았고 Inspector 연결도 필요 없다. 기존 Unity 참조를 사용한 게임 C# 컴파일을 통과했다. Windows 빌드는 새로 만들지 않았다.

최소 검증 결과: Unity의 TestScene에서 스크립트를 가져오고 Play로 시작 화면의 별도 진입 버튼과 형상 봉인자·기존 하수인 동시 등장을 확인했다. 첫 불씨 봉인·수직 막대기·봉인 이름·시전 잠금 표시를 확인했다. 정사각형을 봉인된 불씨에 놓았을 때 거부 문구가 표시되고 손패 5장·배치 3회가 유지됐으며, 같은 카드는 방벽에 정상 배치돼 배치 2회·제작 중 1장이 됐다. 턴 종료 후 불씨 봉인이 해제되고 방벽으로 이동했으며 방벽의 기존 정사각형이 그대로 남았다. 적 공격 합계 8이 한 번 적용돼 HP 50→42, 턴 2·배치 3회·5장 드로우도 확인했다.

실제 피해에 따른 해제·피해 0·다른 적 피격·완성된 봉인 도안 시전 거부·도안 이동·사망·전투 종료·재시작·망치·접착 회귀는 추가 실행하지 않아 미검증이다. 이 경로는 모델·UI에서 연결했으며 컴파일 통과와 코드 검토를 실제 플레이 통과로 간주하지 않는다. 사용자의 최소 검증 요청에 따라 추가 반복 검증은 하지 않았다.

확인 방법: TestScene 열기 → 자산 새로고침 → Play → `형상 봉인자 전투`. 첫 봉인과 막대기를 보고 봉인 도안에 카드 배치를 시도한다. 다른 도안에 놓은 조각은 턴을 종료해 그 도안이 봉인돼도 유지되어야 한다. 불씨가 봉인됐다면 턴을 종료해 다른 도안으로 바꾼 뒤 불씨를 완성하고 형상 봉인자를 공격한다. HP가 12→6으로 줄면서 즉시 봉인과 막대기가 사라지고, 다음 턴 종료까지 재봉인되지 않아야 한다. 기존 하수인만 공격했을 때는 봉인이 유지되어야 한다. 완성한 도안이 다음 봉인 대상이 되면 완성 상태와 조각은 유지되면서 시전 버튼은 잠겨야 한다.

## 2026-11-11 도둑손

TestScene의 `도둑손 전투` 버튼으로 기존 하수인과 도둑손이 함께 나오는 첫 전투에 진입한다. 기존 시작·봉인자 버튼과 SampleScene 진행은 보존한다. HP 12·공격 4는 임시 재사용값이며 별도 진입에서는 첫 주문 튜토리얼을 생략한다.

일반 퍼즐 조작 가능 시간 15초를 누적하고 실제 배치된 카드 한 장을 균등 무작위로 고른다. 입력 없이 대기하거나 카드·도안을 조작할 때도 진행한다. 망치·접착·도움말·메뉴·대상 선택·진행을 막는 안내·UI 비활성화·포커스 이탈·전투 밖에서는 타이머와 이동을 멈추고 재개 시 이어간다. 기존 적 턴은 동기로 처리하므로 실시간 절도 Update와 중복 실행하지 않는다. 대상이 없으면 주기를 완료한 상태로 기다리다가 배치 카드가 생길 때 시도한다. 시도가 끝나거나 목표가 무효화되면 다음 15초를 처음부터 센다.

접근 손은 화면 안의 격자 바깥 후보 중 목표에서 최소 360 UI 좌표 떨어진 곳에서 생성한다. 임시 속도는 초당 90 UI 좌표다. 목표의 현재 점유 삼각형 중심을 추적하므로 카드·도안 이동과 회전에 대응한다. 손은 동시에 하나만 존재하며 외부 이미지 없는 손바닥·손가락 그래픽의 실제 영역을 클릭해야 저지된다. 클릭은 뒤쪽 격자로 전달하지 않는다. UI 재생성은 현재 대상·누적 시간·접근 위치를 유지한다.

도착하면 모델이 원본 카드 인스턴스와 현재 배치를 재검증해 배치에서 절도 보관소로 옮긴다. 배치 횟수는 환불하지 않고 손패·뽑기·버림 더미에도 넣지 않는다. 목표를 먼저 회수·포기·시전 소비하면 접근을 취소하며 다른 카드를 즉시 훔치지 않는다. 이동·회전과 잔상 첫 시전처럼 배치가 유지되면 계속 추적한다. 도둑손 사망은 접근만 취소하며 이미 훔친 카드는 전투 종료까지 보관한다.

원정 소유 덱은 수정하지 않는다. 전투 종료 시 보관소·목표·손을 정리하고 기존 원정 덱 복구를 사용해 원본 ID와 보상 카드, 접착 원본이 중복되지 않게 한다. 특수 효과·잔상 이력·접착 정보는 훔친 카드 참조에 유지하며 임시 망치·접착 변환은 기존처럼 다음 전투에 원정 덱으로 돌아간다.

설정은 SpellGameUI의 도둑손 프로토타입 필드인 `_theftIntervalSeconds`(15초), `_theftMoveSpeed`(90)다. Bootstrap으로 동적 생성하므로 Play 중 Inspector 조정은 해당 실행에만 적용된다. 지속 기본값은 코드 초기값을 바꾼다. 등장 위치·최소 거리·도착 반경 12도 임시 연출 설정이다.

변경 파일: SpellGame.cs, SpellGameUI.cs, 신규 SpellThiefHandGraphic.cs와 .meta, PRD.md, README.md. 추가 Inspector 참조 연결·씬 수정·패키지 변경은 없다. 게임 C# 컴파일 통과, 스크립트 .meta 누락·Assets 중복 GUID 없음. 테스트 코드·테스트 프레임워크·테스트 자산과 새 Windows 빌드는 만들지 않았다.

## 2026-11-11 조각 저주술사

TestScene → Play → `조각 저주술사 전투`로 기존 하수인과 함께 등장한다. 첫 손패 준비 직후부터 매 플레이어 턴 한 장을 저주한다. HP 12·공격 4는 기존 하수인 임시 재사용값이며 별도 공격 패턴은 없다. 첫 턴 선제 저주·매 턴 반복은 관찰을 위한 테스트 기준이다. 빈 손패에는 적용하지 않는다. 주기와 실패 수치는 SpellGame의 CURSE_INTERVAL_TURNS(1), CURSE_FAILURE_AMOUNT(10)에서 조정한다. 정식 SampleScene과 기존 신규 적 진입은 유지한다.

CardCurse는 실제 Card 참조와 적용 턴, 해결 행동(None/Spell/Hammer), 실패 효과(HPDamage), 수치를 보관한다. 카드 이름·목록 인덱스로 추적하지 않는다. 손패의 빨간 테두리·저주 이름·경고와 카드 ID 안내를 표시하고 배치 후에도 점유 구역에 빨간 선을 그린다. 재렌더는 저주를 다시 추첨하지 않는다. 선택 시와 망치·접착 카드 이름에도 저주를 표시한다.

Cast의 유효성 검사를 통과한 실제 시전에서 해당 카드가 소비되거나 잔상으로 남는 시점에 해결한다. 배치와 완성만으로는 유지한다. 망치는 결과가 여러 장으로 생성되어 원본 손패가 교체된 뒤에만 해결한다. 취소·거부·대상 선택만으로는 해결하지 않는다. 기존 망치는 유효한 분해의 첫 단계를 보장하므로 확률 타격 실패를 새로 만들지 않았다. 최소 1/4·손패 공간·사용 횟수 거부는 기존 그대로다.

접착 확정 시 대상 참조를 결과 복합 카드로 이전하고 적용 턴·미해결 상태는 유지한다. 그 복합 카드의 실제 시전 또는 기존 망치 분해로 해결할 수 있다. 회수·이동·회전·도안 포기·절도 등은 저주를 해제하지 않는다. 원정 소유 덱과 특수 효과, 잔상 및 배치 환불 이력은 변경하지 않는다.

EndTurn은 손패를 버리기 전에 현재 저주를 분리해 한 번 판정한다. 미해결이면 ApplyCurseFailure가 HP를 최대 10 직접 감소시키며 방어는 소비하지 않는다. 이는 이번 HPDamage의 테스트 기준이다. HP 0이면 즉시 기존 패배로 전환해 적 행동을 생략한다. 생존하면 기존 적 공격·드로우를 진행하고 새 손패에서 저주한다. 저주술사 사망 후 새 저주는 생성하지 않지만 이미 걸린 저주를 사망만으로 해제하지 않는다. 전투 종료·타이틀·재시작에서 상태를 정리한다. 실패 조건과 효과 적용을 분리했으며 다른 효과를 추가할 때 enum과 적용 분기를 확장한다. 미사용 효과나 범용 상태 이상 시스템은 만들지 않았다.
